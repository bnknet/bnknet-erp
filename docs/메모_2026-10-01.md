## A. 결재 상신자 빈 값 문제 (PR #338, 완료)
- 증상: 강웅구가 09-30 상신한 지출결의서(BNKNET, 64,322,867원)가 승인완료 후 본인 결재 목록에 안 보임. 다른 문서는 정상.
- 원인: 해당 문서의 `submitter_name`이 **빈 값**으로 저장됨(담당자 organizer는 '강웅구'). 로그인 세션이 만료된 상태(`me.name` 없음)로 상신하면 빈 값이 들어가는 빈틈 — 목록은 상신자 이름으로 필터하므로 본인 목록에서 사라짐.
- 코드 수정: `handleSave`에서 로그인 정보 없으면 저장 차단 + 재로그인 안내 (재발 방지).
- 데이터 보정: `db/상신자빈값_보정_20261001.sql` — submitter_name을 organizer로 복원. **사용자 실행 완료, 목록 표시 확인("잘 보인다")**. 같은 증상 점검 쿼리 포함(추가 건 보고 없음).
- 참고: 일반 직원 결재 목록 = 본인 상신 문서 전부(+강웅구는 박정진 문서 열람 가능). 기본 필터 '전체', 표시 10건 제한(더보기).


## B. 주문별 판매 시점 원가 고정 (unit_cost) — 완료
- 배경(실장 질문): 입고 단가가 바뀌면 재고 원가를 평균단가로 고치려는데, 그러면 과거 판매분 공헌이익도 바뀌는가? → **바뀌는 구조였음**. 공헌이익을 항상 '현재 재고 원가'로 재계산(주문에 원가 미기록). 예외는 오픈마켓 실정산 반영 주문(정산 파일 원가)과 도매·로켓그로스·과거실적(manual_cost).
- 결정(실장): 주문 저장 시점 원가로 고정. 이후 원가를 바꾸면 그 뒤 저장되는 주문만 새 원가, 이전 데이터는 불변.
- 구현(커밋 051533d):
  - `db/order_unit_cost.sql` — `orders.unit_cost numeric`(개당, 세트는 구성품 합). **사용자 실행 완료.**
  - `src/lib/salesStats.ts` — `makeUnitCostResolver`(저장 시 원가 계산, computeOrderLines와 같은 규칙) 추가. `computeOrderLines`는 unit_cost가 있으면 그 값×수량으로 계산(없으면 기존처럼 현재 재고 원가). 실정산 보정이 있으면 기존대로 정산 원가 우선.
  - `OrdersContent.tsx` — 파일 변환 저장·직접등록(수기) 저장 시 unit_cost 기록. 원가 0/미등록이면 null(0으로 굳히지 않음). 원가 조회 실패해도 저장은 진행(null).
  - 조회 컬럼에 unit_cost 추가: 매출현황·주문조회·슬랙봇(profit 계열 2곳).
  - `scripts/backfill_unit_cost.ts` — 기존 주문에 현재 원가를 1회 기록(null만, 재실행 안전, 전/후 월별 공헌이익이 다르면 자동 중단). 실행: `npx tsx scripts/backfill_unit_cost.ts [--apply]`.
- 실행 결과: 일반·수기 41,756건 중 **40,945건 원가 기록**, 811건은 원가 없음(재고 원가 0/미등록)으로 null 유지 — 주영엔에스 오메가3 미니 592, 하루틴 비타민C 스틱 62, 매스티나 토너 56, 더블아이 아세로라C 56 등.
- 검증: ① 기록 전/후 22개월 월별 공헌이익 차이 0원 ② 기록 후 DB 기준으로 덴프스 원가를 가상으로 −3,000원 바꿔 재계산 → 전 기간 차이 0원(과거 불변 확인). tsc·build 통과.
- 운영 메모: 원가 변경은 재고관리에서 평소처럼 수정하면 됨(변경 후 저장되는 주문부터 적용). null 811건은 해당 상품 원가 입력 후 스크립트 재실행으로 고정. 부분취소는 수량만 줄어 개당 원가 유지.
- 참고: `npm run build`가 OneDrive 잠금(EPERM, `.next/static/<옛 빌드ID>`)으로 실패하면 그 폴더 삭제 후 재실행.
