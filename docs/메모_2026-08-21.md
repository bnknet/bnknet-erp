## A. 선결제 처리 화면 개선 (PR #319)
- 매입 헤더 표시 개선: **구매일 = 지출결의서 세부내역(approval_items.item_date)** 기준(여러 날이면 범위), `cardLabel`(담당자·카드명), **상신자** 추가. 모달 오픈 시 품목 날짜 50건 배치 조회(실패 시 spend_date 폴백).
- 선결제 버튼 권한: `canPrepay = canManage + 강웅구(email)` (PR #318, 전일) — 카드 관리 권한은 기존 유지.

## B. 선결제 원상복구·이력·경고문 (PR #320)
- **원상복구 기능**: 선결제 처리 모달에서 매입 펼침 → "↩ 이 매입의 선결제 원상복구" (canManage=대표·실장 전용). prepaid_date/prepaid_at null → 한도 재차감·캘린더 원복. `card_logs` '선결제복구' 이력 기록(목록에 [복구] 배지).
- **이력 간소화**: 항목 전체 나열 → **카드별 요약**(카드·N건·금액). 기존 장문은 2줄 클램프.
- **결재 폼 경고문**: '선결제(한도복구)' 선택 시 — ERP에 카드구매 결재 있는 건은 이중복구되므로 카드매입→선결제 처리 사용, 이 결재는 기준값 이전 카드값 전용.
- 잘못 처리된 선결제 3건(비앤케이넷 국민 16,782,700 / 이미림 하나 12,528,000 / 이미림 삼성 20,808,000)은 새 복구 기능으로 사용자 복구 완료.

## C. 선결제 개념 확정 (Q&A)
- ERP에 카드구매 결재가 있는 건의 조기결제 = **카드매입→한도현황→선결제 처리**(품목 체크).
- 결재의 **선결제(한도복구)** = ERP 등록 전(기준값 이전) 카드값 상환 **전용**. 중복 상신 시 한도 이중복구.
- 독립 선결제 결재는 **영구 크레딧**(매입은 결제일 경과 시 자동 소멸) → 짝 없는 크레딧이 잔여한도를 계속 부풀림 = 카드값 불일치의 구조적 원인. 이전 사용분 소진 후 이 메뉴 제거 검토.
