## A. 주문변환 수량 인식: 수량 뒤 영문 꼬리표(BN 등) 대응 (PR #293)
- **증상**: 더블아이(ESM지마켓/옥션) 데이즈온 그린 아세로라C 주문에서 옵션 2/3/4/6개가 전부 수량 1로 잡힘.
- **원인**: 수량은 상품명 끝의 "N개/박스/포/세트"를 끝-앵커(`$`) 정규식으로 추출. 이 상품은 `"…분말 2개 BN"`처럼 "N개" 뒤에 `BN` 꼬리표가 붙어 끝이 아니게 되어 인식 실패 → 수량 1.
- **수정**: `orderConvert.ts`의 수량 정규식(`extractQtyAndName`, `TRAIL_QTY_RE`)에 끝의 짧은 영문 꼬리표(`[A-Za-z]{1,4}`)를 허용.
  - `"…N개 BN"` → 수량 N 인식 ✅
  - `"…60캡슐 12개월분"`(개월분·뒤가 한글)·중간 "N개"·"…, 100ml" 등은 계속 미인식 → **회귀 없음**(node 테스트로 확인).
- 교훈: 끝-앵커를 무작정 풀면 "12개월분"의 "12개"를 오인식함 → 영문 꼬리표만 좁게 허용.

## B. 이미 등록된 아세로라 8건 수량 보정 (SQL)
- 코드 수정 전 등록된 8건은 quantity=1로 저장돼 있어 별도 보정.
- `db/orders_qty_fix_daysone_acerola_20260807.sql`: order_number로 quantity를 2/3/4/6으로 UPDATE(멱등).
- 주문번호/수량: 2154974008=2, 2154973989=3, 2154973993=3, 2154974016=3, 2154974014=4, 2154974007=4, 2154974015=6, 2154974013=6.

## C. 재고 정합성 보정 (핵심 — 재고는 저장식 차감)
- **중요 개념**: 재고 차감은 실시간 집계가 아니라 등록 시점 "자동출고(`/rpc/ship_orders`)"로 재고수량을 깎아 저장. `orders.stock_deducted` 플래그로 관리. → orders.quantity를 나중에 SQL로 고쳐도 재고는 자동 재차감 안 됨.
- **진단(데이터)**: 8건 모두 stock_deducted=true지만 등록 당시 quantity=1이라 각 1개씩만 차감(inventory_logs 합=1/건). 부족분 합계 = 23개.
  - 부족분: 2개→1, 3개(3건)→6, 4개(2건)→6, 6개(2건)→10 = 23.
- **보정 완료(사용자)**: 더블아이 아세로라 재고(id d4339ca2-9b39-4689-9c6f-e701381bed99) 850 → 827 (−23).
  - `update inventory set quantity = quantity - 23 where id = 'd4339ca2-...';`
- 결과: 기존 차감 8 + 추가 23 = 31 = 실제 주문수량 합과 일치. 수량·재고·매출/출고 집계 모두 정합.
