## D. 방성훈 우리카드 잔여한도 보정 (PR #327 폐기 → #328 최종, SQL 실행 완료)
- 증상: 화면 잔여(11,049,498) vs 카드사 앱(약 8,521,200) — 차이 2,528,298.
- 1차 오판: 선결제 결재(22,314,978)가 이전사용분(19,786,680)보다 초과라 보고 품목 축소 SQL 제안 → **대표가 결재 문서로 반박**: 6/26 덴프스 **203개=22,314,978 실구매와 결재가 정확히 일치** = 올바른 기록.
- 진짜 원인: **기준값 이전 사용분 집계가 180개(19,786,680)로 23개 부족** — 실제는 203개.
- 최종 조치: 결재는 보존, **기준잔여만 15,185,022**(=37,500,000−22,314,978)로 보정(`db/방성훈우리_기준잔여_보정_20260825.sql`, 실행 완료). 기대 잔여 8,521,200 = 카드사 앱 일치. (품목 축소 SQL 파일은 삭제·폐기)
- **⭐ 원칙 확립(전 카드 일괄 정리에 적용)**: 차이 발생 시 "결재 기록 vs 기준잔여" 중 **실물(결재 문서·카드사 앱)과 맞는 쪽을 먼저 확인** — 결재 기록이 실구매와 일치하면 절대 수정하지 않고 기준잔여를 보정한다.
