## A. 한도 증액했는데 사용률이 그대로 (실장 문의)
- 증상: 이미림 국민카드 한도 8,400,000 → 16,700,000원으로 수정(11-16 15:15, 방성훈). 한도현황 사용률 97~98% 그대로.
- 원인(데이터 확인): 한도현황 사용액 = (한도 − 기준 잔여한도) + ERP 미결제. 카드 수정 화면에서 '전체 한도'만 바꾸고 '기준 잔여한도'(8,400,000)는 그대로 저장돼, 증액분 8,300,000원이 전부 '이전 사용분'으로 잡힘 → 잔여 364,407원 불변.
- 데이터 정정(ERP API 적용 완료): 기준 잔여한도 8,400,000 → 16,700,000. `card_logs` '기준잔여 조정' 기록. 화면 공식 재현: 사용 8,035,593 / 잔여 8,664,407 / **사용률 48%**. 기록: `db/이미림국민_한도증액_기준잔여조정_20261116.sql`.
- 코드 수정(`src/app/cards/CardsContent.tsx`):
  - 카드 수정 시 기준 잔여한도 칸을 손대지 않았으면 **기존 값 + 한도 변동분**으로 자동 저장(증액·감액 모두). 칸을 직접 고쳤으면 입력값 우선. 신규 등록은 기존대로(비우면 전체 한도).
  - 같은 수정으로 잠재 버그도 해소: 기준 잔여한도가 0인 카드(방기현 포인트 카드 등)를 수정 저장하면 0이 '비움'으로 처리돼 전체 한도로 덮어쓰이던 문제 → 이제 기존 값 보존(0·음수 포함).
  - 한도 공유 그룹(limit_group)은 한 장의 한도를 바꾸면 그룹의 다른 카드 한도도 함께 변경(그룹 한도는 하나). 기준 잔여한도 조정은 수정한 카드에서 한 번만.
  - 저장 응답 검증(실패 시 알림) 추가, 변경 로그에 "한도 변경 A → B (기준 잔여한도 C → D 자동 조정)" 기록, 수정 화면에 조정 예정 금액 안내 문구.
- 점검: 카드 수정 이력상 한도가 바뀐 적 있는 카드는 이미림 국민카드 1장뿐(다른 카드 영향 없음). 기준잔여 ≠ 한도인 카드 다수는 기준값 이전 사용분 설계에 따른 정상 값.
- 검증: tsc·build 통과. 수정 화면에서 한도를 바꿔 저장하는 동작은 실장 확인 필요.
