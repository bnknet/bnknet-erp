## A. 카드 한도현황 결제건 → 원본 기안서 연결 (PR #289)
- 카드 한도현황의 미결제(사용중) 결제건 클릭 → 그 결제건을 올린 **원본 기안서(결재 상세)** 로 이동.
- 결제건 id = 결재 문서 id 이므로 `/approval?id=<id>` 로 라우팅.
- 파일: `CardsContent.tsx`(useRouter, onClick router.push), `ApprovalContent.tsx`(진입 시 `?id=` 읽어 loadDetail 자동 오픈).

## B. 결재 상세 → '한도현황으로' 돌아가기 버튼 (PR #290)
- 한도현황에서 넘어온 경우 결재 상세 상단에 `← 한도현황으로` 버튼 노출 → `/cards` 복귀.
  (기존엔 '목록으로'만 있어 결재 목록으로만 돌아가던 불편 해소.)
- 신호: 링크에 `&from=cards` 부착 → 상세에서 `from===cards`일 때만 버튼 표시(목록에서 직접 연 문서엔 안 보임).
- 파일: `CardsContent.tsx`(링크에 &from=cards), `ApprovalContent.tsx`(useRouter, cameFromCards 상태).

## C. 카드 기준 잔여한도(opening_balance) 개념 정리 + 재설정 SQL
- **원리**: 실시간 잔여 = 기준 잔여한도(opening_balance) − ERP 미결제 결재분 + 선결제 복구분.
  즉 opening_balance = "ERP로 사용내역 잡기 직전(6말/7초)의 잔여한도"(출발점). 결재/선결제/차감 금액은 정상이면 건드릴 필요 없고 **출발점만 맞추면 실시간 잔여가 자동으로 맞음**.
- **주의**: 이 칸에 "현재 남은 한도"를 넣으면 ERP 결재분이 이중 차감됨. 반드시 "사용 전" 값.
- **한도 공유(limit_group) 카드**: 로직이 그룹 내 카드들의 opening_balance를 **합산**(`CardsContent.tsx:450`).
  → 공유 그룹은 "한 장에 목표값 · 다른 장에 0"으로 넣어 합계가 목표가 되게 함.
- 대상(사용자 제공 사용전 잔여한도):
  - 조현상 신한(8183, 단독) → 155,360
  - 조현상 하나(4155, 단독) → 2,179,540
  - 방기현 농협(그룹 방기현_농협) 합계 9,361,240 → 2008=9,361,240 / 6006=0
  - 방기현 우리(그룹 방기현_우리) 합계 1,700,662 → 2936=1,700,662 / 3885=0
- SQL: `db/cards_opening_balance_reset_20260807.sql` (id로 정확 지정, 멱등).
